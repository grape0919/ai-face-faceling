# 오프라인 실험 (Phase 0-A)

"텍스트 의미로 만든 표정이 보기에 좋은가"를 실시간 제약 없이 확인하는 도구다.
녹음된 대화를 미리 정렬하고 분석해 두고, 같은 대화를 세 가지 동작 수준으로 재생·녹화해 비교한다.

| 수준 | 내용 |
|---|---|
| L0 | 오디오만: 립싱크, 턴 상태, 깜빡임, 일정 간격 끄덕임 |
| L1 | + AI 가 말하는 구간의 부위별 표정 |
| L2 | + 사용자가 말하는 동안의 듣기 반응 |

깜빡임과 미세한 머리 움직임은 세 수준에서 똑같이 일어난다. 영상 사이의 차이는 표정 레이어뿐이다.

## 빠른 시작 (키 없이)

저장소 루트에서 실행한다.

```bash
npm install
```

```bash
npm run lab:session -- sample-ko --tts sapi
```

```bash
npm run lab:dev
```

브라우저에서 http://localhost:5173/?session=sample-ko&analyzer=mock 을 연다.

이 경로는 Windows 내장 음성, 글자 수 비례 정렬, 규칙 기반 분석기를 쓴다. 도구가 도는지 확인하는 용도이며 **실험 결과로 쓰지 않는다**.

샘플 세션은 두 개다. `sample-ko` 는 감정이 뚜렷한 짧은 대화, `plain-ko` 는 정보 전달 위주의 평범한 대화(여행 계획)다.

내장 한국어 음성이 하나뿐이어서 사용자 쪽은 같은 음성의 음높이와 음색을 낮춰 만든다. 다른 음성이 설치되어 있으면 `FACELING_SAPI_USER_VOICE` 에 이름을 넣어 그대로 쓸 수 있다. 음성을 다시 만들려면 `audio/` 의 해당 WAV 를 지우고 `--tts sapi` 로 실행한다.

## 실제 실험 절차

1. **대화를 준비한다.** `public/sessions/<이름>/script.json` 에 턴별 화자와 텍스트를 적고, 턴별 음성을 `audio/01-assistant.wav`, `audio/02-user.wav` 식으로 넣는다. 16비트 PCM WAV 여야 한다. 2~3분 분량, 정서가 여러 번 바뀌는 대화가 좋다.
2. **키를 넣는다.** 루트의 `.env.example` 을 `.env` 로 복사해 채운다.
3. **정렬과 분석을 돌린다.** 분석기별로 한 번씩 실행하면 `session.<분석기>.json` 이 따로 생긴다.

   ```bash
   npm run lab:session -- <이름> --aligner whisper --analyzer jev
   ```

   ```bash
   npm run lab:session -- <이름> --aligner whisper --analyzer llm
   ```

   실행이 끝나면 분석 호출의 지연(p50, p95)이 출력되고 세션 파일에도 기록된다. 분석 결과는 `cache/` 에 남아 다시 돌릴 때 재사용된다.
4. **표정을 다듬는다.** 뷰어에서 재생하며 고친다. 동작의 생김새는 `src/face/mapping.ts` 의 계수(저장하면 바로 반영), 무엇을 고르게 할지는 `src/shared/regions.ts` 의 선택지 설명이다. 선택지를 바꾸면 `questions.ts` 의 `QUESTIONS_VERSION` 을 올리고 세션을 다시 만든다.
5. **세 영상을 녹화한다.** 수준을 고르고 "처음부터 녹화"를 누르면 끝까지 재생한 뒤 webm 파일이 내려받아진다. **녹화하는 동안 브라우저 창이 화면에 보여야 한다.** 가려지거나 최소화되면 프레임이 초당 몇 장으로 떨어진다.
6. **3~5명에게 보여 준다.** 파일 이름에서 수준 표시를 지우고 순서를 섞는다. 선호와 어색한 순간을 받는다.
7. **판정한다.** L1 영상이 L0 보다 과반 선호되면 진행한다. 아니면 질문과 대응을 고쳐 한 번 더 한다.

## 표정이 정해지는 방식

분석기(Jev)가 구간마다 **얼굴 부위별로 동작 하나를 직접 고른다.** 부위는 눈썹, 눈, 시선, 볼·코, 입, 머리 6개이고, 표정 세기를 따로 한 번 묻는다. 한 요청에 질문 7개가 들어간다.

- 얼굴은 항상 AI 의 것이다. AI 가 말하는 구간은 말하는 표정을, 사용자가 말하는 구간은 듣는 반응을 묻는다. 두 경우는 질문 문구와 선택지 설명이 따로이고(`regions.ts` 의 `desc` 와 `listen`), 듣는 동안 어울리지 않는 동작은 선택지에서 빠진다.
- 선택지별 확률이 그대로 동작 세기가 된다. 확률 0.2 이하는 버리고 0.7 이상이면 온전히 준다. 둘째로 높은 선택지가 약하게 섞일 수 있다.
- 코드는 동작을 고르지 않는다. 각 동작의 생김새(ARKit 52개 계수), 부위별 반응 속도, 말하는 동안 입 모양과의 우선순위만 정한다.
- 뷰어의 "부위별 동작" 칸에 분석기가 고른 것과 지금 얼굴에 걸린 세기, 지금까지 움직인 blendshape 수가 나온다.

세션 파일 형식이 바뀌었으므로 예전에 만든 `session.*.json` 은 다시 만들어야 한다.

## 옵션

| 옵션 | 값 | 설명 |
|---|---|---|
| `--analyzer` | `mock` | 규칙 기반. 키 불필요. 시험용 |
| | `jev` | TypeSafe Jev. `TYPESAFE_API_KEY` |
| | `llm` | 소형 LLM 대조군. `ANTHROPIC_API_KEY`, 기본 모델 `claude-haiku-5-5` |
| `--aligner` | `naive` | 글자 수 비례 추정. 키 불필요. 부정확 |
| | `whisper` | 음성 인식의 단어 타임스탬프. `OPENAI_API_KEY` |
| `--tts` | `none` | 음성 파일이 없으면 오류 |
| | `sapi` | 없는 턴만 Windows 내장 음성으로 합성. 시험용 |

뷰어 주소의 `session`, `analyzer`, `level` 값으로 무엇을 볼지 고른다.

## 얼굴

뷰어의 "얼굴" 칸에서 고른다. 주소에 `avatar=robot`, `avatar=dog`, `avatar=vrm` 을 붙여도 된다. 기본은 로봇이다.

- **로봇**: 코드로 그린 얼굴(`src/viewer/rig-robot.ts`). 머리는 3D 도형이고 얼굴은 머리 앞 화면에 2D 로 그린다. ARKit 52개 값을 모두 직접 받아 눈, 눈썹, 볼, 코, 입 모양에 반영하므로 모델 파일이 필요 없다. 생김새를 바꾸려면 이 파일의 그리기 코드를 고친다.
- **강아지**: 코드로 그린 2D 얼굴(`src/viewer/rig-dog.ts`). 로봇과 같이 52개 값을 모두 반영한다. 머리 회전은 이목구비를 밀어서 흉내 내고, ARKit 에 없는 귀는 눈썹과 눈 값에 따라 서거나 처진다.
- **VRM 모델**: `public/models/avatar.vrm` 이 있으면 그것을 쓰고, 없으면 three-vrm 예제 모델을 실행 중에 불러온다. "VRM 바꾸기"로 파일을 직접 고를 수도 있다.

VRM 은 **ARKit 52 blendshape 를 가진 모델**이어야 표정이 제대로 보인다. 대부분의 VRM 은 표준 표정(happy, sad, surprised 등) 몇 개만 가지며, 그런 모델에서는 값을 표준 표정으로 뭉뚱그려 옮기므로 비대칭 미소, 눈썹 한쪽 올리기 같은 표현이 사라진다. 뷰어 상단에 어느 방식으로 동작 중인지 표시된다.

## 구조

```
src/
  shared/types.ts          세션 파일 형식, 판단값 타입
  shared/regions.ts        얼굴 부위와 부위별 동작(분석기 선택지) 정의
  pipeline/                준비 단계 (Node)
    cli.ts                 음성 확보 → 정렬 → 분할 → 분석 → 세션 파일
    align.ts               naive, whisper 정렬
    segment.ts             절 단위 분할 (15~40자)
    analyzers/             questions(질문 문구), jev, llm, mock
    tts.ts                 Windows 내장 음성 합성
  face/                    표정 엔진 (브라우저·Node 공용, three 의존 없음)
    cues.ts                부위별 확률 → 동작 세기, 수준별 예약과 순간 동작
    mapping.ts             동작 → ARKit 52 blendshape, 머리, 시선
    engine.ts              레이어 합성과 보간
  viewer/                  재생·렌더링 (브라우저)
    player.ts              턴 음성 재생, 립싱크용 오디오 분석
    rig-robot.ts           ARKit 프레임 → 코드로 그린 로봇 얼굴
    rig-dog.ts             ARKit 프레임 → 코드로 그린 강아지 얼굴
    rig-vrm.ts             ARKit 프레임 → VRM
    main.ts                화면, 녹화
```

부위 정의, 질문, 동작 → ARKit 대응, 레이어 합성, 로봇·강아지 얼굴은 `packages/core` 에 있고 실시간 예제(`apps/realtime`)와 함께 쓴다. 이 폴더의 같은 이름 파일들은 그것을 다시 내보내기만 한다.

## 아직 확인하지 못한 것

- **LLM, whisper 경로는 실제 키로 호출해 보지 않았다.** 요청·응답 형식은 각 문서를 따랐고 타입 검사는 통과한다. 첫 실행에서 형식이 다르면 오류 메시지에 원인이 나온다. Jev 경로는 샘플 대화로 실행해 확인했다.
- **ARKit 모델에서 새 동작들이 어떻게 보이는지는 확인하지 못했다.** 값이 나오는 것까지만 봤다. 계수는 초안이다.
- **녹화 파일 내려받기는 실행해 보지 않았다.** 캔버스 녹화 자체가 데이터를 내는 것까지만 확인했다.
- 오프라인판에는 응답 첫 구절의 "시작 표정 선점"이 없다. 모든 판단이 미리 준비되어 있어서 필요하지 않다.
