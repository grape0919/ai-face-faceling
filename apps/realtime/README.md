# 실시간 예제 (Phase 1)

OpenAI Realtime API 로 음성 대화를 하면서, AI 의 얼굴이 말의 뜻에 맞춰 실시간으로 움직인다.
표정은 텍스트만 보고 정한다. 소리는 입 모양(립싱크)에만 쓴다.

## 실행

저장소 루트의 `.env` 에 키를 넣는다.

```
TYPESAFE_API_KEY=...   # Jev (표정 판단)
OPENAI_API_KEY=...     # 음성 대화. 없으면 모의 대화만 된다.
```

```bash
npm install
```

```bash
npm run rt:dev
```

브라우저에서 http://localhost:5174 를 연다. 처음 열면 세 단계 안내가 나온다.

1. 소개
2. 얼굴(로봇, 강아지, 3D 모델)과 목소리 고르기
3. "마이크 허용하고 대화 시작" 또는 "텍스트로만 대화할게요"

다시 열면 안내 없이 대화 화면이 나오고, "대화 시작"을 누르면 연결한다. 안내를 다시 보려면 주소 끝에 `?onboarding` 을 붙인다. 고른 얼굴과 목소리, 안내를 마쳤는지는 브라우저의 localStorage 에 남는다.

- **연결하면 AI 가 먼저 인사한다.** 응답 한 번만큼 요금이 나온다. 개발자 패널에서 끌 수 있다.
- **마이크 버튼**은 연결을 끊지 않고 소리 입력만 막는다.
- **텍스트로만 대화**하면 마이크 없이 연결한다. 글로 말을 걸고, AI 의 답은 소리로 나온다. 마이크를 허용하지 않았을 때도 이렇게 넘어간다.
- **캐릭터 변경**은 연결을 유지한 채 얼굴을 바꾼다. 목소리는 연결한 뒤에 바꿀 수 없어서, 목소리를 바꾸면 다시 연결한다.
- **대화 기록**은 오른쪽(좁은 화면에서는 아래) 칸이다. 글 입력창도 여기 있다. 넓은 화면에서는 처음부터 열려 있다.

OpenAI 키가 없으면 "예시 대화 보기"로 표정 경로를 볼 수 있다. 음성 대화 서비스가 보내는 것과 같은 순서로 사건을 흘려 넣고 Jev 는 실제로 부른다. 소리는 나지 않고 입은 가짜 값으로 움직인다.

### 개발자 패널(안쪽 보기)

`` ` `` 키를 누르거나 주소 끝에 `?dev` 를 붙이면 연다. 부위별로 지금 걸린 동작과 세기, 시점 통계, 전체 목소리 목록, "AI 가 먼저 말하기"·"말 끊기", 말하는 도중의 반응 켜고 끄기, 내 VRM 불러오기, 문장 하나로 시험하기가 있다.

## 동작 방식

```
마이크 ──WebRTC──> OpenAI Realtime ──오디오 트랙──> 스피커, 입 모양 분석
                        │
                        └─데이터 채널(텍스트 조각, 재생 시작·끝, 사용자 말 시작·끝)
                                │
                          LiveDirector ──절마다──> 서버 /api/judge ──> Jev
                                │   (부위별 동작 + 세기)
                                ▼
                            LiveFace ──매 프레임──> ARKit 52 값 ──> 로봇·강아지 얼굴
```

1. **절로 끊기.** AI 응답 텍스트가 조각으로 올 때마다 문장 끝과 쉼표에서 끊는다(15~40자).
2. **절마다 Jev 호출.** 부위 6곳의 동작과 표정 세기를 받는다. 여러 절을 동시에 보낸다.
3. **소리 시각 추정.** 재생이 시작된 시각에 "그 절 앞까지의 글자 수 × 글자당 시간 + 문장부호 뒤 쉼"을 더해 그 절이 들릴 시각을 추정한다. 글자당 시간은 응답이 끝날 때마다 실제 재생 시간으로 고쳐 나간다.
4. **예약.** 판단이 그 시각보다 먼저 오면 그 시각에 걸고, 늦게 오면 도착한 때부터 건다. 절의 소리가 이미 지나갔으면 버린다.
5. **끼어들기.** 사용자가 말을 끊으면 예약된 표정을 모두 거둔다.
6. **듣는 반응.** 사용자가 말하는 도중에도 들리는 대로 반응한다. 대화용 연결은 말이 끝난 뒤에야 전사를 보내 주므로, 같은 마이크 소리를 전사만 하는 두 번째 연결(`gpt-live-transcribe`)에도 보내 글자를 실시간으로 받는다. 10글자쯤 새로 들릴 때마다 듣는 사람 기준 질문으로 Jev 를 부르고, 말이 끝나 최종 전사가 오면 한 번 더 판단한다. 화면의 "말하는 도중에도 반응"을 끄면 두 번째 연결을 열지 않고 말이 끝난 뒤에만 반응한다.
7. **시작 표정 선점.** 응답의 첫 절이 길면 완성되기 전에 앞머리 6글자쯤만 보고 먼저 판단해 걸어 두고, 첫 절의 판단이 오면 그쪽으로 넘어간다.

### 맥락

절 하나를 판단할 때 그 절만 보내지 않는다. 직전 대화 4개 대사(사용자와 AI 의 말)와, 같은 응답에서 바로 앞에 한 2개 절을 함께 넘긴다. 바로 뒤에 이어질 말도 도착한 만큼(최대 80자) 함께 넘긴다. "정말요?", "아,"처럼 4글자 이하의 짧은 절은 뒷말을 들어야 뜻이 정해지므로, 뒷말이 12글자쯤 도착할 때까지 판단을 미룬다. 그래서 "정말요? 강아지가 아프다니 너무 슬퍼요."의 "정말요?"는 걱정하며 놀라는 얼굴이, "정말요? 와, 축하드려요!"의 "정말요?"는 기뻐하며 놀라는 얼굴이 된다. 사용자의 최종 전사는 AI 가 답하기 시작한 뒤에 오는 경우가 많아서, 그 전까지는 도중에 들린 글자를 맥락에 쓴다.

같은 말이 맥락에 따라 다르게 판단되는 것을 확인했다. 예를 들어 AI 의 "그랬군요."는 앞말이 "시험에 합격했어요!"이면 미소와 끄덕임, "강아지가 세상을 떠났어요."이면 눈썹 안쪽 올림과 입꼬리 내림으로 나온다. "참 잘하셨네요."는 앞말이 "고객 자료를 전부 지워 버렸어요."이면 한쪽 미소와 가로젓기 쪽으로 바뀐다.

### 판단 기록

서버는 Jev 를 부를 때마다 `logs/judge-날짜.jsonl` 에 한 줄씩 남긴다. 어떤 맥락으로 무엇을 물었고, 부위별로 무엇이 뽑혔고, 얼마나 걸렸는지가 들어 있다. 표정이 어색했던 순간을 찾을 때 본다. 대화 내용이 들어 있으므로 저장소에는 넣지 않는다.

개발자 패널의 "시점" 칸에 Jev 응답 시간, 판단이 소리보다 얼마나 먼저 왔는지, 응답 첫 절의 표정이 소리보다 얼마나 늦었는지, 놓친 절 수가 나온다.

## 구조

```
server.ts          @faceling/server 로 임시 키 발급·Jev 중계, 화면 설정(/api/config), 판단 기록, 화면 파일 제공
src/simulate.ts    모의 대화
src/main.ts        화면(온보딩, 대화 화면, 개발자 패널)
public/brand/      로고(심볼, 조합형)
```

이 예제는 저장소의 패키지만 가져다 쓴다. 다른 앱에 붙일 때도 같은 패키지를 쓰면 된다(루트 README 의 "내 앱에 붙이기").

| 패키지 | 여기서 쓰는 것 |
|---|---|
| `@faceling/core` | 표정 엔진(`live.ts`, `compositor.ts`, `clauses.ts`) |
| `@faceling/openai-realtime` | OpenAI Realtime 어댑터(`connection.ts`: WebRTC 연결, 사건 → LiveDirector)와 말하는 도중의 전사를 받는 두 번째 연결(`transcriber.ts`) |
| `@faceling/rigs` | 로봇·강아지 얼굴과 VRM 연결 |
| `@faceling/server` | `/api/session`, `/api/transcription-session`, `/api/judge` 처리기 |

개발 중에는 패키지를 빌드하지 않는다. `npm run rt:dev` 는 `faceling-source` 조건으로 각 패키지의 TS 원본을 바로 읽는다. 브라우저 쪽 패키지는 고친 뒤 화면을 새로 고치면, `@faceling/server` 는 서버를 다시 시작하면 반영된다.

다른 음성 대화 서비스에 붙이려면 `packages/openai-realtime/src/connection.ts` 에 해당하는 어댑터만 새로 쓰면 된다. LiveDirector 가 받는 사건은 다음이 전부다.

| 메서드 | 언제 부르나 |
|---|---|
| `assistantStarted()` | AI 응답이 만들어지기 시작 |
| `assistantText(delta)` | 응답 텍스트 조각 도착 |
| `assistantTextDone()` | 응답 텍스트 끝 |
| `assistantAudioStarted()` | AI 음성이 실제로 재생되기 시작 |
| `assistantAudioStopped()` | AI 음성 재생 끝 |
| `assistantInterrupted()` | 사용자가 끼어들어 음성이 끊김 |
| `userSpeechStarted()` / `userSpeechStopped()` | 사용자 말 시작·끝 |
| `userPartial(text)` | 말하는 도중에 들린 글자(이번 발화의 처음부터 지금까지). 없어도 된다 |
| `userTranscript(text)` | 사용자 말의 최종 전사 도착 |

## 보안

- OpenAI 와 Jev 의 키는 서버에만 있다. 브라우저는 몇 분짜리 임시 키만 받는다.
- 서버는 `127.0.0.1` 에만 열린다. 다른 기기에서 접속하게 하려면 `/api/judge`, `/api/session`, `/api/transcription-session` 앞에 인증을 먼저 넣어야 한다. 그대로 열면 누구나 내 키로 호출할 수 있다.
- 대화 텍스트(AI 응답과 사용자 말의 전사)가 표정 판단을 위해 Jev 로 전송된다.
- "말하는 도중에도 반응"을 켜면 마이크 소리가 OpenAI 의 전사용 연결에도 전송되고, 그만큼 전사 요금이 더 나온다.

## 한계와 확인하지 못한 것

- **로고는 래스터 시안이다.** `public/brand/` 의 PNG 는 배경을 지운 시안이고, 어두운 배경에서만 쓴다. 출시 전에 SVG 로 다시 그리고 작은 크기(파비콘)용 버전을 따로 만들어야 한다.

- **실제 연결에서 확인한 범위(2026-11-12, `gpt-realtime-2.1`).** 사람 목소리 대신 녹음된 음성을 마이크 자리에 넣어 음성 경로 전체를 돌렸다(주소에 `?fakeMic=/dev/파일.wav`). 말하는 도중의 글자가 0.4초쯤 간격으로 들어왔고, 말하는 도중에 듣는 반응이 걸렸다. 응답의 첫 표정은 소리보다 0.4초쯤 늦었고(선점을 넣기 전에는 첫 절이 길 때 1초), 놓친 절은 없었다. Jev 응답은 평균 220~290ms 였다. 표본이 작아 참고 수준이다.
- **스피커 소리가 마이크로 돌아오는 경우.** AI 가 말하는 동안 들어온 글자는 버리도록 했지만, 이어폰 없이 스피커로 들을 때 실제로 어떤지는 확인하지 못했다.
- **응답의 첫 표정은 소리보다 0.3~0.4초 늦다.** Jev 를 한 번 부르는 시간이다. 사용자가 방금 말한 뒤라면 듣는 반응이 그 사이를 이어 준다(AI 가 말을 시작한 뒤 1초까지 유지).

- **절의 소리 시각은 추정이다.** 말 빠르기가 고르지 않으면 표정이 조금 이르거나 늦게 걸린다.
- **말투는 읽지 않는다.** 글자로는 칭찬인데 비꼬는 말투인 경우처럼 소리에만 있는 정보는 반영되지 않는다. 필요하면 Audio2Face 같은 오디오 기반 도구와 함께 쓴다.
